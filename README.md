# meeting-agent

一个会议纪要问答 Agent。用中文提问，它自己决定查哪场会、用什么关键词查，
查不到会换个词再查，最后带着出处回答。

不是封装好的框架，是从零写的循环，目的是把 Function Calling 的执行流程
一步步跑清楚。

## 跑起来

```bash
export DEEPSEEK_API_KEY="你的 key"
pip install openai
bash demo.sh                      # 跑完四个预设场景
bash demo.sh "你自己的问题"        # 问一个问题
```

## 结构

```
data.py    3 条模拟会议纪要。真实系统里来自转写服务 + 数据库。
tools.py   2 个工具 + 给模型看的 JSON Schema
             list_meetings()        列出有哪些会
             search_notes(keyword)  按关键词搜正文
agent.py   主循环
demo.sh    一条命令跑完四个场景
```

## 核心循环

模型本身不执行任何代码。它只能说「我要调 `search_notes`，参数是 `成本`」，
真正执行的是本地代码，执行完把结果作为 `role="tool"` 的消息塞回对话，
再问模型一次。

```
① messages = [系统规则, 用户问题]，连同工具 schema 发给模型
        ↓
② 模型回话。检查 msg.tool_calls
        ↓
   有 → ③ 本地执行对应函数
        ④ 结果 append 回 messages，回到 ①
   无 → 模型在作答，返回答案，结束
```

`MAX_ROUNDS = 5` 兜底，防止模型一直要工具导致死循环和 token 消耗失控。

## 四个场景的真实输出

**1. 多步检索 + 自我修正**

```
问：上个月模型调用成本超了多少？谁负责去拉明细？

[第1轮] search_notes({'keyword': '模型调用成本'}) → 0 条
[第1轮] search_notes({'keyword': '成本'})         → 2 条
[第2轮] 模型不要工具了，给出答案

→ 超出 Q4 预算 30%，主要来自长会议切段；小王负责拉明细并按时长分桶；
  李姐下周一前跟采购确认追加额度。来源：2026-10-12《产品周会》
```

窄关键词搜不到时，模型自己换了更宽的词。这是 Agent 和单次 Chat Completion
的区别——它能根据工具返回的结果决定下一步。

**2. 选对工具**

```
问：我们都开过哪些会？
[第1轮] list_meetings({}) → 3 条
```

问"有哪些"时它选了 `list_meetings` 而不是 `search_notes`。工具选择由
schema 里的 description 驱动。

**3. 跨字段归纳**

```
问：转写在中英混说的场景下问题有多严重？

→ 中文字错率 5.2%、英文 4.8%，中英混说掉到 12%；原因在语言边界切分；
  加 prompt 提示语言种类有改善但不稳定；换 ASR 方案成本高暂不动。
  来源：2026-10-15《技术评审 - 转写准确率》
```

**4. 拒绝编造**

```
问：区块链那场会上决定了什么？

[第1轮] list_meetings({})                → 3 条
[第1轮] search_notes({'keyword':'区块链'}) → 0 条
[第2轮] → "没有关于区块链的会议纪要，我无法回答决定了什么。"
```

系统提示里写了「工具查不到就直说查不到，不要猜」，这条规则生效了。

## 已知缺陷

**关键词匹配搜不到同义表述。**

```python
search_notes("准确率")  # → 0 条
```

有一场会叫《技术评审 - 转写准确率》，但正文里写的是「字错率」，
三个字对不上就搜不到。这是字符串匹配的天然上限，加再多关键词也绕不开。

正确的解法是把检索换成向量检索：把纪要切块、做 embedding 存进向量库，
查询时按语义相似度召回，「准确率」和「字错率」在向量空间里是近的。

其他限制：

- 数据是硬编码的 3 条，没有接真实存储
- 工具写死在 `REGISTRY` 里，加工具要改代码（MCP 这类协议解决的就是这个）
- 只有单轮问答，没有多轮对话的上下文管理
- 没有自动化评估脚本，目前是手工跑这四个场景看输出

## 下一步

2. 搭一个小评估集（能答的 / 同义词不匹配的 / 不存在的），跑成自动化脚本，

3. 多轮对话 + 上下文管理
